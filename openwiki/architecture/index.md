# Files

- [Python Client, CLI and Transports](client-cli-and-transports.md) - How the powercontext CLI entry point assembles its command groups, how the Python PowerContextClient and shared transport policy choose endpoints and HTTP consent, how host native configuration and setup select transports, and how Codex session import is scoped, redacted and checkpointed.
- [Desktop App (Tauri Preview)](desktop-app.md) - Internal Tauri 2 desktop shell for PowerContext on Windows and macOS. Covers the native Rust host (connections, sessions, credentials, Ops bridge, session observations, diagnostics), the React UI, the trusted IPC allowlist, generated wire and IPC types, and the local-server operations boundary. Preview status only, not a signed or supported release.
- [Inference Gateway (pc-gateway)](gateway.md) - Explains the Rust pc-gateway crates, the two-phase before_send and before_release gate execution with Core gate clients, retry and no-duplicate-send rules, degradation, failure-to-status mapping, shutdown, and the body-free evidence output.
- [HTTP and MCP API Surface](http-and-mcp-api.md) - Public wire surfaces of the PowerContext Server (versioned /v1 HTTP routes, the generated OpenAPI document, generated Python client models, and the curated MCP tool projection), with the authentication, ETag/If-Match, and Dream-contract headers agents must send and the error branches they must handle.
- [Persistence and Storage Backends](persistence-and-storage.md) - How the PowerContext Server selects SQLite, embedded seekDB, or OceanBase storage, which tables hold which state, how managed schema revisions and maintenance run, and which admission checks guard startup. Read before changing schema, migrations, or persistence code.
- [PowerContext Server Runtime](server-runtime.md) - How the PowerContext Server process is assembled from settings, the CLI, the FastAPI factory, HTTP admission and authentication middleware, per-route authorization, the built-in runtime and its artifact processing supervisor, and the readiness and shutdown lifecycle.
- [Source Map](source-map.md) - Maps repository directories to the systems that own them (Python packages, HTTP contract, Desktop, integrations, examples, gateway, deploy, docker, scripts) and lists which generated or derived files must be regenerated instead of hand-edited. Use it to decide where a change belongs and which generator or gate to run.
- [PowerContext System Overview](system-overview.md) - Explains PowerContext's owned systems (Scope, Source, Artifact families, runtime and background workers, Server, Client and CLI, Ops and service management, Gateway, host integrations), how they relate, when Sources are captured versus Artifacts committed, when Candidate review applies, and the ownership boundaries to respect when changing code.
